- (event) Fixed long/dense T&Cs failing: max_tokens was hardcoded at 4096, causing truncated JSON on dense documents (many flaggable clauses), which the regex-only parser rejected outright (502 to the user). Raised max_tokens to 16000 (tested sufficient on a 38-clause synthetic dense document) and made truncation recoverable: handler detects stop_reason===max_tokens and parseClauses falls back to a string-aware scan that salvages every complete clause object before the cutoff. Response now carries a truncated flag; client renders a truncation notice instead of failing. Verified locally against the real Pulse endpoint: full fix returns 200/untruncated on the repro doc, and an artificially re-capped token budget still returns 200 with partial results and truncated:true instead of a hard failure.
